# 涨停监控：昨日封板与开盘竞价

用户已确认直接实施四列，并同步手机卡片和 CSV 导出。

- 昨日首封、昨日终封：实际行情日期之前最近交易日的首次、最后封板时间，HH:mm:ss。
- 昨日竞价、今日竞价：各交易日最终开盘价相对该日行情参考昨收价的涨幅，带正负号、两位小数和 %；真实零显示 0.00%。不使用盘中涨幅。
- 昨日由交易日历确定，以实际行情日期为锚点，包括历史查询、周末和盘前回退。行情行的 trade_date 和指标的 context_date 均记录实际行情日期，previous_trade_date 记录该行情日期的前一交易日。昨日未触板、无开盘数据等空值显示 —。
- 在主导航“涨停监控”主页面（Dashboard，/）及涨停列表（LimitUpList，/limit-up）同时增加字段。桌面四列、手机卡片、CSV 使用一致格式。
- 两页显示昨日日期，CSV 包含行情日期和昨日日期。两页统一在筛选区提供首封、回封、昨日终封、昨日竞价、今日竞价、封单、连板排序按钮；昨日终封不增加列头排序。时间默认从早到晚，竞价默认涨幅从高到低；空值和无效值始终置后，同值按股票代码升序；实时更新保持选择的排序。
- 取消查询按钮。日期、连板、题材、状态、价格及排序操作自动查询；价格输入短暂防抖，预设/重置各触发一次，请求更新后旧响应不能覆盖新筛选。刷新和导出保留。

用户已明确确认：例如查询 2026-10-26（周一）盘前，行情回退到 10-23（周五），昨日指标取 10-22，今日竞价取 10-23 的最终开盘值。上海九百昨日终封应为 10:52:37；09:25:00 属于 10-23 的回封时间。选择日期改变不应让同一行情日期的昨日指标发生偏移。

## Approach

用户选择直接扩展现有列表。沿用实时腾讯批量行情获取当日 open/pre_close；历史日线补齐昨日与历史查询开盘涨幅。历史未复权日线的 close-change_amount 作为同日参考昨收，防止除权口径混用。昨日封板优先批量读取数据库事实，必要时补查历史涨停池。历史补充按日期和股票缓存、限制并发和等待；不阻塞已有告警快速通路。实时富数据和 HTTP 均携带四字段，推送保留一致性。

线上验证发现历史源会间歇限制访问。因此增加每日开盘事实归档：当前监控行情保存经交易日期和 09:25 完成时间验证的开盘百分比；独立后台任务按日抓取全市场当日行情补齐归档。文件位于 backend/data/opening-auctions/YYYY-MM-DD.json，原子合并写入；昨日及历史查询优先读取归档，再查历史源。该任务不阻塞监控响应，异常可重试；已有日期通过可核验历史来源回填。归档属于运行数据，部署保留。

监控首屏只等待涨停池、当前行情和有总等待上限的昨日信息；涨停原因使用有效缓存并后台刷新，流通股本按交易日缓存并后台补齐。首次缺少的流通市值随下一次完整快照补入。非监控调用保留原来的等待行为。

休市日禁止把来源返回的上次行情标成当天：HTTP 先确认交易日，周末及经权威交易日历确认的节假日使用数据库实际交易日；竞价与昨日封板信息按实际行情日期计算。日历不可核验时使用同一历史回退，无法确定昨日则留空。初始 WebSocket 快照、完整推送和告警轮询也校验交易日，避免错误日期覆盖 HTTP 回退；时间判断采用中国时区。

交易日盘前同样可能只有上一交易日行情。东方财富 qdate 表示最新可用日期，历史查询可以早于该日；请求日超出该日时必须拒绝旧涨停池，清除错误日期的缓存，并使用现有数据库实际日期回退。原始爬虫和实时聚合共享此校验，防止把周五行情行错误标成周一，并继续按实际行情日期提供昨日指标。
