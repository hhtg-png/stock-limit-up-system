# 动态板块与历史入选档案设计

日期：2026-10-30。状态：待用户审阅；尚未修改或部署产品功能。

## 用户明确提出的目标

- 类似同花顺的动态分组：按数据条件形成自定义板块，并查看板块走势图。
- 一旦选出股票，就能在以后查看该板块的历史数据。
- 板块指数不能仅从生成日期开始：股票选出后，立即可用这些股票的历史行情合成生成之前的板块走势。
- 沿用现有系统盘中自动刷新、用户操作后自动查询的交互习惯。

## 核心方案

把“当前成分”和“历史入选档案”分别保存。每次首次命中、重新加入、退出及规则变更均留下记录；历史不会因为最新条件或行情变化而被覆盖。

历史页可以选择交易日及当日批次，看到当时的规则、股票、入选时指标、生成前历史指数和后续表现。盘中入选后又退出的股票也能查到；不要求打开浏览器才开始记录。

主要走势图默认使用当前选中批次的固定成分回溯计算，首次生成即可看历史；切换旧批次后，使用旧批次的固定成分展示当时那批股票的历史及后续表现。曲线注明“按本次成分回溯”，并标明批次形成时间。用户无需等待板块创建后积累历史。

只保存名单不足以支持走势图，因此同步保存真实行情时间、板块走势点和入选股票的日级行情。现有题材强度分数与价格走势的含义不同，图表不能混用。

## 待用户答复及可配置项

已询问：规则分组或系统题材归类、全沪深或涨停相关池、首次入选后保留或动态退出。

以下是实施建议，不作为用户已经同意的内容：

- 先做规则分组，支持自定义名称、“全部满足 / 任一满足”。系统自动发现题材不属于本次建议范围。
- 建组时可选择“全沪深 A 股”或“今日触板及昨日涨停”；建议默认全沪深。
- 建组时提供两种成员方式：“持续跟踪”（命中后保留至手动移出）和“动态进出”（不再命中时退出当前名单）。两种方式都永久保留入选档案。建议默认持续跟踪，最终根据用户对“一旦选出来”的解释调整。
- 手动移出会记录退出事件，下一次重新满足规则时仍可重新入选；停用分组才停止新入选。此行为在操作文案中说明。

## 首批条件

市场 / 代码 / 名称、排除 ST、股价、实时涨幅、今日最终开盘竞价涨幅、换手率、成交额、流通市值、今日触板 / 当前封板、今日连板数、昨日涨停 / 昨日连板数、昨日首封和昨日终封。

- 数值支持大于等于、小于等于、等于及区间；时间支持早于 / 晚于；条件只使用白名单字段和运算符，不执行用户代码或 SQL。
- “昨日”以实际行情日的前一交易日为准，不能以网页选择日期或自然日前一天代替。
- 今日竞价只使用最终开盘价，9:25 前不把试撮价冒充最终开盘；缺失输入保留未知，不能作为 0 参与比较。
- 条件输入未知不构成“不匹配”；无法判断时保留原成员并标记待更新。首次筛选时未知股票不加入，并展示实际数据覆盖情况。
- 行业 / 概念使用现有映射，但必须显示来源更新时间和覆盖范围；不能宣称完整实时的同花顺成分。覆盖缺失仍为未知。
- 昨日竞价作为后续扩展；首版只在现有历史归档确有该数据的范围内开放，不能对全市场逐股同步请求历史造成查询阻塞。

## 页面

新增主导航“动态板块”，不堆入通达信专用页面。

1. 板块列表：名称、规则摘要、成员方式、成员数、更新时间、数据状态；支持新建、编辑、暂停和归档。
2. 当前板块：条件、当前成分股、平均当日涨幅、涨跌家数、固定成分历史指数（默认近一年，可切换近一月 / 三月 / 六月及全部已保存历史）及盘中分时。创建或修改后的新结果异步自动更新，历史行情在后台拉取并入库，界面显示进度；已有历史不等待重新选股。
3. 历史入选：交易日、日内批次、规则版本、当时名单；展示入选时间、价格、竞价、连板、首终封等当时字段。默认选某日最后一批，可以展开盘中批次。
4. 历史批次跟踪：固定所选批次的股票，可以查看生成前历史指数和选出后的日级表现。即使股票已退出当前组，仍能查看这批股票后续表现。
5. 点击个股进入现有个股详情；手机端也能选择日期和批次、查看名单及走势。

图表明确区分“固定成分历史指数”“当前动态板块盘中连续走势”“当前成分平均当日涨幅”和“入选后表现”。成分变化后生成新批次的历史曲线，不把不同批次回溯曲线接成一条连续收益线。

## 历史与计算口径

- 历史指数必须支持生成日期之前。首版后台获取并保存每只成分股最多约 3 年的复权日线，实际可查看起点由真实数据和成分股共同覆盖日期决定；不能假定所有股票都有 3 年历史。时间窗口只改变显示范围，指数基准不随窗口切换漂移。
- 固定成分历史指数采用“期初等额配置、固定股数持有”的明确口径。共同基准交易日为 t0，基点 1000；`I(t) = 1000 × mean(P_adj_i(t) / P_adj_i(t0))`，所有股票使用各自同一来源、同一次获取的统一复权序列。它不等同于每日重新等权再平衡的指数，页面提供简短口径说明。
- 日线图只画真实有效日期。全体成分在基准日和目标日有可验证价格才计算完整点；缺失显示缺口和覆盖率，不临时删去股票改变分母。新股导致可用共同历史缩短时，显示实际起点及原因。确认停牌的数据可依可靠估值规则结转，普通缺数不可推定为停牌。
- 为精确复查，保存固定成分签名、基准日、各股复权基准价、数据源和序列修订版本，以及合成指数点。后续除权或源数据修订由整段同口径序列重新核验，记录修订；不能把新旧复权价直接追加混算。
- 历史回溯曲线使用该批次选中的固定成分；历史选股档案从系统实际选中时记录。首版不提供“过去某天按当时条件会选中谁”的全市场规则回测，避免把这两种历史含义混淆。
- 当前板块指数首次有效观测为 1000 点；按分钟计算。使用上一有效时点已确定成员计算下一段等权收益，再按当前规则调整下一段成员；新成员加入前的涨幅不注入指数。退出成员先结算退出前最后一段。
- 批次后续表现固定该批次成员，使用该批次形成时全体成分同次有效行情的价格作统一时点基准；不能使用成员各自更早的首次入选价。跨日使用相同复权口径核验后的收益序列。历史回溯指数另用统一历史基准日，两个基准分别保存。成员首次入选价只用于该成员的入选档案与其自身入选后表现；后续新入选者不加入旧批次。
- 规则变更创建不可变新版本；历史批次指向原版本。新版本的当前指数单独起算，图中标出生效时间，不静默拼接或重算旧曲线。
- 成员缺失、过期或日期不一致时，不把收益当 0，也不改小分母计算一个看似完整的指数；保留最后有效点、显示缺口及覆盖率。
- 跨日必须验证真实交易日历和相邻交易日。除权使用同一复权序列或经验证的收益参考；原始入选价不可直接除以另一来源的前复权价。无足够依据则该段待补，不能生成伪收益。
- 停牌仅凭可靠状态确认；成员与入选档案保留。普通接口失败不能当作停牌、自动退出或零收益。
- 不生成周末、节假日、午休的伪行情点；恢复采样后，停机期间无真实来源的分时保持缺口。日级真实行情可后台补齐并记录来源、修订原因。

## 数据持久化与调度

独立保存：板块定义、不可变规则版本、带时间的入选 / 退出记录、冻结批次及成员引用、板块走势点、历史入选股票共享日级行情。

- 入选事件保存完整触发字段、规则版本、选中时价格、真实报价时间和数据状态；只记录价格变化不会重复复制全份入选名单。
- 首次筛选成功、成员变化、规则版本变更及收盘时形成批次；同一采样槽重复执行由唯一键保证幂等。共享成员记录，避免每分钟复制大 JSON。
- 跨表写入同一事务：不能只保存当前名单却没有对应历史事件。多个调度实例需由数据库唯一键 / 作业认领防止重复或交错顺序。
- 全市场行情统一拉取并共享一次快照，不能按板块重复扫描；借用现有腾讯批量行情，保留并验证真实时间及缺失字段。涨停和昨日指标分别读取可复用的实时池、数据库及已有归档。
- 按真实交易时段后台计算，不依赖网页轮询。初始建议规则扫描 30 秒、聚合分时每分钟一条；实际频率以全市场采集耗时核验后确定，页面显示真实更新时间。
- 收盘生成每日最终批次和日级表现；所有曾入选股票继续积累共享日级行情，暂停新选股也不会删除或停止既有历史批次的后续表现记录。
- 服务重启从数据库恢复最新规则、成员、计算基准及任务进度。失败任务可重试，不用新空结果覆盖成功记录。
- 历史 API 只读数据库；缺失的日级后续行情后台补全，先返回已保存的历史。每个日期和批次都返回实际数据状态、时间，不显示空白成功。
- 归档板块为软删除；不删除已选历史。永久清理不属于本次功能。

## 接口边界

独立 `/api/v1/dynamic-groups` 路由提供：定义增改查 / 启停 / 归档、规则预览、当前成分、已有历史日期、某日批次、批次详情、当前板块分时、指定批次日级后续表现。

所有批次和走势查询验证所属板块；未知 ID 返回 404。限制查询时间范围和返回点数；按数据库索引分页，不能一次返回全量历史。新建或编辑后立即排队计算，HTTP 不等待全市场扫描完成。

## 可复用位置与实际限制

- `backend/app/services/live_market_stats_service.py`：已有全沪深代码和批量行情扫描，目前仅缓存汇总，需共享个股快照。
- `backend/app/data_collectors/tencent_api.py`：价格、昨收、开盘、涨幅、量额、市值、真实时间和缺失字段。
- `backend/app/services/limit_up_context_service.py`：实际行情日及前一交易日、昨日首终封和竞价。
- `backend/app/services/local_topic_knowledge_service.py`：本地题材映射，有覆盖与时效限制。
- `frontend/src/views/tdx/TdxPlateStrength.vue`：可参考 ECharts、响应式和过期请求保护；现有强度趋势不是收益指数。
- 现有股票表和复盘日表仅覆盖部分股票，不能当作完整全市场历史库；已有分时兜底未严格核验请求日期，不能拿来回填任意日期的板块分时。

## 验收

1. 股票在盘中入选后退出，收盘 / 重启后仍能查到原入选批次、触发数据及时间。
2. 规则修改、归档板块不改变旧批次的名单和规则；旧批次仍可查后续表现。
3. 切换历史日期不会用当前数据重跑规则；历史查询耗时不受外部行情请求影响。
4. 新增或退出成分不会凭空跳涨指数；缺失报价、除权、跨日、停牌或停机不会生成错误连续收益。
5. 自动采样无需打开网页；交易日历、重复采样、任务恢复、跨板块批次越权均有验证。
6. 手机端、日期 / 批次切换和自动刷新可用，慢请求不会覆盖用户后来选中的历史批次。
7. 前后端检查通过后提交 GitHub 并部署；核验线上规则保存、真实入选、历史读库、资产版本与截图后报告结果。
